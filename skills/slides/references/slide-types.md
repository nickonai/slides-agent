# Типы слайдов и поля YAML

Сценарий — YAML-список слайдов (или словарь с ключом `slides`). Холст
1280×720, PNG рендерится в 2×.

```yaml
- title: ЧЕМ ИИ-АГЕНТ ОТЛИЧАЕТСЯ
  slide_type: title
  subtitle: Простыми словами
  body: [Без кода, На примерах]
  presenter_notes: Что говорить на этом слайде.
```

## Типы

| `slide_type` | Фон | Для чего |
|---|---|---|
| `title` | тёмный | титул: знак и название бренда, надстрочная метка, заголовок, тезисы-чипсы из `body` |
| `agenda` | светлый | нумерованный список: повестка, результаты |
| `bullets` | светлый | рабочий тип: заголовок и 3–5 строк с линейками |
| `cards` | светлый | 2–4 равнозначных пункта карточками |
| `steps` | светлый | путь из 3–5 пронумерованных шагов со стрелками |
| `stat` | светлый | одна крупная цифра в начале заголовка и подтверждения карточками |
| `comparison` | светлый | было / стало: две колонки, ✕ и ✓ |
| `statement` | светлый | одна фраза во весь экран; строки `body`, если есть, идут списком под ней |
| `feature` | тёмный | текст слева; справа скриншот в макете браузера (`image`), крупная величина (`figure`) или цепочка шагов (`chain`); без них — только текст |
| `screenshot` | светлый | крупный скриншот; со строками `body` — текст слева, кадр справа |
| `docs` | светлый | 2–3 документа или изображения с подписями |
| `author` | светлый | о спикере: история слева, портрет без фона справа |
| `case` | кремовый | история человека: утверждение, факты, подпись, оговорка; фото по желанию |
| `stack` | тёмный | нарастающий список «Название — сумма» с итогом. **Только по прямой просьбе** |
| `pricing` | светлый | три тарифа в ряд. **Только по прямой просьбе** |
| `closing` | синий | финал: призыв, тезисы, плашка `cta` |

Без `slide_type` тип угадывается: первый слайд — `title`, последний —
`closing`, заголовок начинается с числа — `stat`, строки со «СТАР…»/«НОВ…» —
`comparison`, иначе `bullets`. Лучше указывать явно.

## Поля

| Поле | Где работает | Что делает |
|---|---|---|
| `title` | все | заголовок; капс пишем сами. В `stat` — «число + подпись», в `case` и `author` — имя |
| `subtitle` | все | подзаголовок; в `feature`, `cards`, `steps`, `stat`, `agenda`, `comparison`, `docs`, `stack` — надстрочная метка; в `case` — главное утверждение |
| `body` | все, кроме `docs` и `pricing` | строки; маркеры `❌`/`✕` → красный ✕, `✅`/`✓` → галочка, `🎯`/`→` → строка результата полужирным |
| `presenter_notes` | все | заметки докладчика: в PPTX и в HTML-деке |
| `footnote` | все | мелкая строка внизу: источник или обязательная оговорка |
| `eyebrow` | `title`, `case` | надстрочная метка; иначе из `brand.yaml` |
| `cta` | `closing` | текст плашки; иначе `cta` из `brand.yaml`; пусто — без плашки |
| `image`, `crop`, `url` | `screenshot`, `feature` | картинка, доли обрезки `[слева, сверху, справа, снизу]`, адрес в макете браузера (иначе `site` бренда) |
| `figure`, `figure_label`, `figure_note` | `feature` | карточка с одной крупной величиной: «3 шага · Сколько нужно · пояснение» |
| `chain`, `chain_title`, `active` | `feature` | список шагов или модулей; `active` (с 1) подсвечивает текущий |
| `badge` | `feature`, тарифы | жёлтая плашка над заголовком или над тарифом |
| `left_label`, `right_label`, `left`, `right` | `comparison` | подписи и явные списки колонок; иначе колонки собираются по маркерам `❌`/`✅` |
| `photo`, `role` | `case`, `author` | портрет и подпись под именем (иначе `case.role` бренда) |
| `documents` | `docs` | список `{file, caption, crop}` |
| `tariffs` | `pricing` | список `{name, price, badge, lines, note}` |
| `visual_note` | все | служебная пометка, на слайд не попадает |

Поле, которого шаблон не знает, генератор отмечает `⚠` в логе — такое поле
на слайд не попадает.

## Картинки

- Путь — относительно YAML-файла или абсолютный. Удобно: `WORK/images/`.
- Картинки ужимаются и вшиваются в HTML как data:URI — дек остаётся одним файлом.
- Форматы: PNG, JPEG, WebP — всё, что открывает Pillow.
- Картинка пользователя с людьми или документами — сначала проверь: нет ли на
  ней персональных данных (телефон, e-mail, адрес, номер документа, QR с
  реквизитами). Есть — обрежь `crop` или попроси другую.

## Правила вёрстки, которые держит генератор

1. **Зона окна спикера** (флаг `--speaker-zone`): правый верхний угол 340×200
   пустой — туда ложится картинка спикера в трансляции. Заголовки переносятся
   раньше, правые колонки опускаются ниже. Заезд печатается
   `⛔ заезжает в зону спикера`.
2. **Поля.** Контент не заходит на колонтитул и за правое поле:
   `⚠ выходит за поля на N px`.
3. **Кегли под телефон:** основной текст 24–31px, заголовки 36–96px по длине
   строки, метки 17px. Мельче 20px — только сноска.
4. **Заголовки:** интерлиньяж 1.1 (точки над «ё» и дуга «й» не упираются в
   строку выше), кегль ограничен шириной колонки по самому длинному слову.
5. **Переносы:** «ИИ-агенты», «чат-бот» не рвутся по дефису; «12 месяцев»,
   «49 900», тире — с неразрывным пробелом.
6. **Один мотив:** знак бренда крупно, почти прозрачно, за краем кадра
   (`motif` в `brand.yaml`).
