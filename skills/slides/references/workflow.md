# Презентатор — правила агента

Единые правила для Claude Code, Codex и загружаемого навыка ChatGPT. Корневой `AGENTS.md` и `SKILL.md` ссылаются сюда.

Работай на русском, если пользователь не попросил другой язык.

## Что делает агент

Превращает любой контент — тему, текст, файл, ссылку, заметки — в презентацию
в фирменном стиле:

```text
YAML-сценарий слайдов
  → <name>-deck.html   один файл, листается стрелками, шрифты и картинки вшиты
  → png/               каждый слайд 2560×1440
  → <name>.pptx        слайды-картинки + заметки докладчика
  → <name>.pdf         векторный, печатью из HTML
  → <name>-mobile.html все слайды лентой для телефона, один файл
```

Бренд (название, знак, палитра, шрифты, плашка финала) задаётся `brand.yaml`.
По умолчанию — пресет Универус.

## Пути

| Обозначение | Что это |
|---|---|
| `SLIDES` | папка скилла. В клоне репозитория (Codex) — `skills/slides`. В плагине Claude Code — base directory скилла `slides`, её показывает загрузка скилла |
| `PY` | Python окружения. После `SLIDES/scripts/setup.sh`: `~/.slides-agent/venv/bin/python` (macOS, Linux) или `%USERPROFILE%\.slides-agent\venv\Scripts\python.exe` (Windows). Если есть `uv` — можно `uv run` вместо `PY`: зависимости объявлены в заголовках скриптов |
| `WORK` | папка презентации: `presentations/<slug>/` в текущей рабочей папке пользователя. `slug` — латиница через дефис |

Если `PY` не существует — сначала запусти `SLIDES/scripts/setup.sh`
(Windows: `SLIDES\scripts\setup.ps1`) и скажи пользователю, что ставишь
окружение. Команды одинаковы в Claude Code и Codex.

## Процесс

1. **Запрос.** Пойми тему, аудиторию, цель («объяснить», «продать идею»,
   «отчитаться»), длину (по умолчанию 8–12 слайдов) и где будут показывать:
   трансляция с окном спикера или нет. Если чего-то критичного не хватает —
   задай до трёх коротких вопросов разом. Если исходник есть (текст, файл,
   ссылка) — прочитай его целиком.
2. **Ресёрч — по необходимости.** Нужен, когда в исходнике нет фактов, а
   презентация о них. Ищи в вебе, записывай в `WORK/sources.md`: утверждение →
   ссылка → дата доступа. На слайд идут только факты из этого файла. Если веба
   нет — скажи об этом и строй слайды без цифр.
3. **План.** Покажи пользователю план: номер, тип слайда, заголовок, одна строка смысла.
   Если пользователь просил сначала согласовать план — жди ответа. Если поручил
   сделать презентацию целиком, продолжай сборку, оставив план в `WORK/plan.md`.
4. **YAML.** Пиши `WORK/slides.yaml` по плану — поля и типы в
   [`slide-types.md`](slide-types.md).
   В `presenter_notes` — что говорить на слайде, 1–3 предложения.
   Картинки пользователя клади в `WORK/images/`, в YAML — путь относительно
   YAML-файла (или абсолютный).
5. **Сборка.**

   ```bash
   PY SLIDES/scripts/build_deck.py WORK/slides.yaml --out WORK/build --name <slug>
   ```

   Флаги: `--speaker-zone` — оставить правый верхний угол 340×200 под окно
   спикера в трансляции (`--safe-w/--safe-h` — размеры, `--safe-guide` —
   подсветить зону); `--only 2,5` — пересобрать выборку; `--html-only` — без
   рендера; `--no-pdf`, `--no-mobile`; `--brand путь/brand.yaml`;
   `--eyebrow`, `--cta` — перебить метку титула и плашку финала из бренда.
6. **Самопроверка.** Обязательна, до выдачи:
   - в логе сборки нет строк с `⛔` и `⚠`, последняя строка —
     `[check] слайдов с замечаниями: 0`;
   - открой глазами **каждый** PNG из `WORK/build/png/`: переносы, наезды,
     пустоты, обрезанные слова, «висячие» предлоги, лишний капс;
   - поле, которого шаблон не знает, на слайд не попадает — сверь, что всё из
     плана видно на картинках;
   - прогони текст по правилам ниже.
   Нашёл проблему — правь YAML и пересобирай, а не рисуй вокруг.
7. **Выдача.** Назови пути: `<slug>-deck.html` (показывать), `<slug>.pptx`
   (с заметками), `<slug>.pdf`, `<slug>-mobile.html` (отправить в мессенджер).
   Коротко: сколько слайдов, какие источники, что осталось на решение
   пользователя.

## Правила стиля

- **Заголовок капсом + 3–4 короткие строки.** Заголовок — до двух строк.
  Строка — одна мысль, до ~60 знаков.
- **Одна мысль — один слайд.** Не помещается — дели на два слайда.
- **Крупно, под телефон.** Презентацию смотрят с мобильного: шаблоны держат
  основной текст 24–31px, заголовки 36–96px. Не уменьшай кегль, сокращай текст.
- **Без мелких сносок-спойлеров.** `footnote` — только для источника или
  обязательной оговорки, не для «ещё одной мысли».
- **Ритм фонов.** Светлый — объяснения. Тёмный (`feature`, `title`) — главное,
  продукт, пример. Синий — только финал. Два тёмных подряд — только внутри
  одного блока.
- **Слева смысл, справа доказательство** на тёмных слайдах: скриншот,
  крупная величина или цепочка шагов.
- **Визуал только со смыслом.** Никаких стоковых картинок, иконок и цветных
  эмодзи: маркеры `❌`/`✅`/`🎯` генератор сам заменит на ✕ ✓ →. Фото и
  картинки — только реальные, от пользователя или скриншоты.
- **Стиль не переизобретаем.** Новый слайд собирается существующими типами.

## Правила текста

- **«вы» со строчной**, с прописной — только в начале предложения.
- **Сроки — «12 месяцев»**, не «год» и не «12 мес». «Навсегда» — для бессрочного.
- **«Вечная» презентация — без дат и времени суток.** Если пользователь не
  привязывает её к событию: ни года, ни месяца, ни «сегодня в 19:00», ни версий
  моделей и сервисов.
- **Позиционирование утверждением.** «Разработчик, создатель платформы», а не
  «не инфобизнесмен, а практик».
- **Числа не рвутся.** Генератор сам ставит неразрывные пробелы в «12 месяцев»,
  «49 900» и перед тире; составные слова через дефис не переносит.

## Правила фактов и людей

- **Факты — только из источников.** Цифры, проценты, даты, названия
  исследований — из исходника пользователя или `WORK/sources.md`. Нет
  источника — нет цифры. Не выдумывай кейсы, отзывы, доходы, регалии,
  дефицит и гарантии.
- **Кейс — только с согласия человека.** Тип `case` ставим, только если
  пользователь подтвердил, что человек согласен на показ имени, фото и цифр.
  Иначе — обезличенный пример без фото с пометкой «пример».
- **Без персональных данных.** Никаких телефонов, e-mail, адресов, номеров
  документов, ID, ссылок на личные профили, QR с реквизитами — даже если они
  есть в исходнике.
- **Тарифы по умолчанию не делаем.** Тип `pricing`, слайды с ценами, рассрочкой
  и рублёвой «ценностью» (`stack` с суммами) не используем, пока пользователь
  прямо не попросит. Если попросил — в каждой карточке тарифа только новые
  отличия от предыдущего: старший тариф открывается строкой «Всё из Базового»,
  дальше — только то, чего в нём нет.
- **Имена конкурентов** не ставим, если это не сравнительное исследование.

## Свой бренд

Скопируй `SLIDES/brand.example.yaml` под именем `brand.yaml` в рабочую папку
(или в `WORK/`) и поправь. Порядок поиска: `--brand` → `brand.yaml` рядом с
YAML-сценарием и выше до папки с `.git` → переменная `SLIDES_BRAND` →
`SLIDES/brand.yaml` → пресет `SLIDES/presets/univerus/brand.yaml`. Какой бренд
подхвачен, сборка печатает первой строкой `[brand]`.

Свои шрифты: `PY SLIDES/scripts/fetch_fonts.py --dir <папка> --css "<ссылка Google Fonts>"`,
затем `fonts.dir`, `display`, `sans`, `mono` в `brand.yaml`.

## Если правишь сам генератор

- Код: `SLIDES/scripts/`. Дизайн-примитивы: `SLIDES/assets/design/`.
- Новый тип слайда: функция `t_<name>(s, page, cfg)` в `build_deck.py` на
  примитивах `slides.css`, заголовок через `title_of(s, steps, top_w())`,
  правая колонка не выше `panel_offset()` при включённой зоне спикера,
  регистрация в `TEMPLATES` и `KNOWN_FIELDS`, строка в `SLIDES/references/slide-types.md`.
- Проверка: собрать демонстрационный `examples/ai-agent-vs-chatbot/slides.yaml`,
  если он доступен в репозитории. Лог без `⛔`/`⚠`, просмотреть PNG.
  Код должен идти на Python 3.10+.
- В репозиторий не коммитим выходные файлы презентаций без прямого запроса.
